\section{Queries are functors from problem statements to solutions}

In this and the following chapters we are going to build towards the solution of co-design problems.
We will consider an arbitrary graph of \SY{design problems}, in which nodes are \SY{design problems} and edges are arbitrary interconnections between functionality and resources, obtained through the operations of a \SY{traced monoidal category} (series, parallel, feedback) plus the \SY{lattice} structure (and, or) of \SY{design problems}.
On this structure we want to solve the query \FixFunMinRes (\cref{prob:FixFunMinRes}) or, symmetrically, \FixResMaxFun (\cref{prob:FixResMaxFun})

We look at this from a compositional point of view.
We will assume that we know the solution to \FixFunMinRes for each of the components.
We think of the components as primitive blocks, because they are given in a catalogue format as a DPI, or they are special cases ($+$, $\mtimescat$, \etc) which we will solve as special cases.
Given the solution for the primitive blocks, we want to know what is the solution for \FixFunMinRes for the entire diagram.

What is the form of the solution that we expect?
Given a DP~$\adp\colon \funsp \profto \ressp$ we expect the solution to \FixFunMinRes to be a function that, given a fixed functionality~$\fun\setin\funsp$, returns the set of required resources which make the given fixed functionality feasible (with respect to $\adp$). Such a set of required resources has the structure of an \SY{upper set}.

\begin{definition}
    \label{def:ftoR-dp}
    Given a DP~$\adp\colon\funsp\profto\ressp$ we denote by~$\widehat{\adp} \colon \funsp\op\toinPos \tupp{\uppersets \ressp, \setsubseteq}$ the monotone function that associates to each functionality~\fun the set of required resources which are sufficient to realize~\fun:
    \begin{equation}
        \begin{aligned}
            \widehat{\adp}\colon \funsp\op & \toinPos \tupp{\uppersets \ressp, \setsubseteq}, \\
            \fun                      & \mapsto \makeset{ \res \setin \ressp \colon \adp(\fun, \res)}.
        \end{aligned}
    \end{equation}
    In particular, if a certain functionality~\fun is infeasible, then~$\widehat{\adp}(\fun)=\Emptyset$.
\end{definition}

\begin{remark}[Monotonicity]
    For any DP~$\adp\colon\funsp\profto\ressp$, the associated function $\widehat{\adp} \colon \funsp\op\toinPos \tupp{\uppersets \ressp, \setsubseteq}$ is indeed monotone: given $\fun\F{'}\posleq \fun$ in $\funsp\op$ (so $\fun\F \posleq  \fun\F{'}$ in $\funsp$), we have
    \begin{equation}
            \widehat{\adp}(\fun\F{'}) = \makeset{ \res \setin \ressp \colon \adp(\fun\F{'}, \res)} \subseteq \makeset{ \res \setin \ressp \colon \adp(\fun, \res)}  =\widehat{\adp}(\fun)
    \end{equation}
        by the monotonicity of $\adp$. 
        
        In words: since $\fun\F{'}$ is \emph{more} functionality than $\fun$ in $\funsp$, the set of required resources that render $\fun\F{'}$ feasible will be \emph{smaller} than the set that renders $\fun$ feasible. 
\end{remark}

Symmetrically, the solution to \FixResMaxFun is given by a function that we call~$\widecheck{\adp}$.

\begin{definition}
    \label{def:rtoF-dp}
    Given a DP~$\adp\colon\funsp\profto\ressp$, define the map~$\widecheck{\adp} \colon \ressp\toinPos  \tupp{\lowersets{\funsp}, \setsubseteq}$ that associates to each required resource~\res the set of functionalities which can be realized with~$\res$:
    \begin{equation}
        \begin{aligned}
            \widecheck{\adp}\colon \ressp & \toinPos \lowersets{\funsp}, \\
            \res                      & \mapsto \makeset{ \fun \setin \funsp \colon \adp(\fun, \res)}.
        \end{aligned}
    \end{equation}
    In particular, if a certain resource~\res leads to no feasible functionalities, then~$\widecheck{\adp}(\res)=\Emptyset$.
\end{definition}

\begin{remark}[Monotonicity]
    Consider a DP~$\adp\colon\funsp\profto\ressp$ and~$\res\posleq \res\R{'}$.
    We have
    \begin{equation}
            \widecheck{\adpa}(\res) =\makeset{ \fun \setin \funsp \colon \adp(\fun, \res)} \setsubseteq \makeset{ \fun \setin \funsp \colon \adp(\fun, \res\R{'})} =\widecheck{\adpa}(\res\R{'}),
    \end{equation}
    by the monotonicity of $\adp$. 
\end{remark}

A question that arises naturally is whether the map~$\widehat{\adpa}$ is sufficient to reconstruct the original DP.
The answer is yes.
We will prove that~$\widehat{\adpa}$ defines a morphism in a category called~\UPos, and that this category is equivalent (\cref{def:cat-equivalence}) to~\DP.
In fact, \FixFunMinRes can be seen as a \SY{functor} from~\DP to~\UPos.
Symmetrically,~$\widecheck{\adp}$ is a morphism in a category \LPos equivalent to \DP and \FixResMaxFun can be seen as the \SY{functor} from \DP to \LPos.

In the course of this chapter, by defining the two \SY{functors}\FixFunMinRes and\linebreak[0] \FixResMaxFun, we effectively have solved the problem of optimization for DPs in the ``mathematical'' way.
However, this is only the first step, because it does not say anything about whether the \SY{functor} is actually computable.
In the next chapter (\cref{chap:solving}) we will look at finite approximations of DPs and the computational complexity of the solution.
Then, we will introduce the theory of \SY{monads}, and based on that, we will be able to show how to construct bounded finite approximations of any DPs.
